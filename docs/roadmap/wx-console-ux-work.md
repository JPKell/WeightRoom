# WX Work — the console experience arc

**Started 2026-09-12** from the operator's request list of the same day
([`history/prompts/wx-operator-request-2026-09-12.md`](../history/prompts/wx-operator-request-2026-09-12.md),
verbatim). Sixty-odd items over the five tabs; this file groups them by the files they collide on,
not by the app they name, because most of them are the same edit five times. Same shape and rules
as [`weightroom-work.md`](weightroom-work.md) (§2 there is the standing preamble; nothing pushed,
tagged or published; **no version bumps** — everything under `## [Unreleased]`).

**Surveyed before scheduling** (four read-only surveys, 2026-09-12; their findings are folded into
the rows). Four facts changed the plan:

1. **MirrorWall's `table.js` already sorts and hides columns** — opt-in is `sortable=true` +
   `table_id=` on the `table()` macro, and no application-tab template opts in. "All tables
   sortable" and "results show/hide columns" are the same one-attribute edit, not a feature.
2. **Three items are already true**: LoadCoach's *declared* is a multi-valued dict (only the
   rendering joins it); LoadCoach has a config file and a generated settings page; the WeightRoom
   brand already sits top-left and links to `/`.
3. **Six items are application features, not console pages**: FreeWeight's machine nickname,
   display name, parameter filter, test-completion aggregate and provider profiles; IdeaPress's
   editable workflows; PromptCadence's ledger cursor; LoadCoach's provider `enabled` flag. Each is
   an additive API change in its own repository, scheduled as such.
4. **Max context that fits VRAM is already measured** — FreeWeight's `memory_kv` benchmark
   (`max_successful_context_tokens`, with `max_context_capped_by_configuration`). Nothing carries
   it out of FreeWeight; the row is a pipe, not a new test.

**Decided by the operator, 2026-09-12** (interview): ECharts is vendored (MirrorWall row, ADR
superseding [ADR-0139](../adr/0139-the-per-page-javascript-budget-is-a-total-of-120-kb.md)),
not server-SVG; IdeaPress editable workflows are built as their own row; FreeWeight provider
profiles are built as their own row (ADR amending ADR-0077); the "model chart" is the dashboard's
models × suites heatmap, which gets a toggle to a models × tests completion matrix.

**Defaults taken without asking** (say so if wrong): FreeWeight's Tokens page goes and the settings
page says to run `freeweight token create` — there is no HTTP mint by design; "allow all tools"
in chat sends the registry snapshot, never an omitted key (auditable); LoadCoach prefix matching
on Reliability is console-side `startswith` over the pairs the page already fetches; a LoadCoach
provider checkbox is a real `enabled` key, not a mass model-disable; the adapters page gets a
**Draft manifest** action (writes `<name>.draft.json` for a person to review — ADR-0061's manifest
stays hand-reviewed) plus a paragraph saying what a manifest is; Goals regroups as *Results*
(installed goals, reports) / *Set up a run* (define, starters, pack, import) / *Runs* (drafts,
calibration); the prompt page shows named inputs for `version`, `metadata.change_reason` and the
template body with the whole record in a collapsed JSON `<details>`.
